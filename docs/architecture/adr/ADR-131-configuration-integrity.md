# ADR-131 — Configuration Integrity aggregation surface

- **Status:** Accepted
- **Date:** 2026-06-07
- **Scope:** `@adjudicate/admin-sdk` (`governance.configSealStatusAll` + `governance.killSwitchTimeline`; `PackConfigSealEntry`/`ConfigSealStatusAllResult`/`SealViolation`/`SealViolationKind` schemas; `KillSwitchTimelineReport`/`KillSwitchStabilityClass`/`KillSwitchEventSource` schemas; `deriveSealViolations` reference helper; `AdminContext.configSealReports?` / `AdminContext.killSwitchTimeline?`), apps/console (unified `/integrity` page), apps/web (public configuration-integrity badge).
- **Related:** ADR-114 (kill switch v2 / `analyzeKillSwitchTimeline` producer + AuditEventBus), ADR-121 (configuration-integrity seal — `verifyConfigSeal`/`sealPackConfig` producer + `governance.configSealStatus`), ADR-128 (web-parity platform / dual-app transparency contract).

## Context

Configuration integrity was split across two unrelated console surfaces and was largely dark. Seal status (ADR-121) lived in one single-pack card (`governance.configSealStatus`) that collapses signature failure, digest mismatch, and policy error into opaque `errors[]` strings, with no multi-pack view and no linkage to the `kill.SEAL_MISMATCH` event a mismatch triggers. Kill-switch history lived on `/control` as a raw `emergency.history` log with no stability assessment — even though `@adjudicate/audit` already ships the pure `analyzeKillSwitchTimeline` producer (a V1 freeze-matrix symbol) that was exposed nowhere over tRPC. Phase-3 / WS3 requires one coherent surface answering an operator's three questions in one screen — which packs verify, what violations exist and what they triggered, how stable the kill switch has been — plus a sanitized public transparency badge.

## Decision

- **`governance.configSealStatusAll`** (new tRPC query) → `ConfigSealStatusAllResultSchema` (`{ entries: PackConfigSealEntry[] }`). One entry per installed pack — `{ packId, packVersion?, report, violations }` — wrapping the existing `ConfigSealReportSchema` verbatim. Additive sibling to `configSealStatus`, which is unchanged. PRECONDITION_FAILED when `ctx.configSealReports` is absent.
- **`governance.killSwitchTimeline`** (new tRPC query) → `KillSwitchTimelineReportSchema`, a structural re-declaration of `@adjudicate/audit`'s `KillSwitchTimelineReport` (the same dependency-free posture `ConfigSealReportSchema` takes toward `@adjudicate/conformance`). The analyzer runs **adopter-side**; the procedure is a pure read of the threaded report — same pattern as `redTeam` / `policyCoherence` / `aiBom`. PRECONDITION_FAILED when `ctx.killSwitchTimeline` is absent.
- **`SealViolationKind`** (new closed enum: `digest_mismatch | signature_failed | signature_missing | policy_error`) + `SealViolationSchema` (`{ kind, message, basisCode }`) + the reference helper **`deriveSealViolations(report)`**. Violations are derived deterministically from the report fields — `digestMatch === "mismatch"` → `digest_mismatch` (basisCode `seal_mismatch`, the `kill.SEAL_MISMATCH` linkage); `signatureVerification.verified === false` → `signature_failed`; `verified === null & reason "not_supplied"` (under `require_signature`) → `signature_missing`; residual `errors[]` → `policy_error`. No new producer in `@adjudicate/conformance`.
- **`AdminContext.configSealReports?` / `AdminContext.killSwitchTimeline?`** — both optional → feature-detectable via PRECONDITION_FAILED, consistent with every other report-backed field. The existing `configSealStatus?` is unchanged.
- **Console:** a unified `/integrity` page with three panels — Active seals (multi-pack `DataTable`), Seal violations (structured chips + `kill.SEAL_MISMATCH` audit linkage), and the Kill-switch activation timeline (stability badge + roll-up tiles + chart, with the existing `EmergencyHistoryList` embedded as the raw log and a cross-link to `/control`). New Sidebar item ("Integrity", `ShieldCheck`). The single-pack `ConfigSealStatus.tsx` card and `/control` controls stay.
- **Web:** a public, read-only `/transparency/integrity` badge fed by a committed *illustrative* fixture projected through the **aggregate-only** `projectIntegrityTransparency` — seal-verified counts + a closed kill-switch stability class, plus `asOf`. No digests, reasons, actors, headline, signature, or per-pack detail ever cross the boundary.

### Mapping note — GovernanceEvent → KillSwitchEvent

`GovernanceEvent` carries `previousStatus`/`newStatus`/`reason`/`actor`/`at` but no explicit `source`, so the console route maps every operator console update to source `operator`. A `DENY_ALL` `newStatus` is a `trip` (state `active`); any other (`NORMAL`) is a `clear` (state `normal`). `emergency.history` is newest-first and `analyzeKillSwitchTimeline` is order-sensitive and does NOT sort, so the handler reverses to chronological order before analysis. An empty history yields a `stable`/empty report rather than throwing — the feature stays available, not PRECONDITION_FAILED.

## Why this shape

- **Additive, pattern-matched.** Both procedures mirror the established context-read + PRECONDITION_FAILED idiom; no new store, no kernel change, no producer change (`analyzeKillSwitchTimeline`, `verifyConfigSeal`, and `kill.SEAL_MISMATCH` already exist with freeze-matrix rows). The multi-pack seal procedure is an additive sibling to the single-pack one — no breakage.
- **Structured violations without a new producer.** `deriveSealViolations` is a pure, deterministic projection of the report fields the adopter already computes, giving the console legible failure modes and a kernel linkage where the single card had only opaque strings.
- **Public-leak defense in depth.** Configuration integrity is the most sensitive surface to publish: digests are config fingerprints, reasons/actors are incident narrative + operator identity, the headline embeds trip counts + engaged-seconds. The public projection is an allowlist whose output type cannot even carry those fields — only two counts + one closed class + `asOf`.

## Invariants preserved

- Determinism/replay untouched — seal verification, digest computation, and timeline analysis are pure observability producers outside the determinism/taint boundary; none feeds `adjudicate()`/`intentHash`/decisions. `analyzeKillSwitchTimeline` deliberately does not sort, so it is byte-stable over the same ordered sequence; the only wall-clock read is the web badge's `asOf`, which lives entirely in app code. The seal gate refuses (does not rewrite), so no taint transition is created.
- No closed-enum widening — `KillSwitchStabilityClass`/`KillSwitchEventSource` are re-declared byte-equal to `@adjudicate/audit`; `SealViolationKind` is new but derived (additions would only ever be MINOR); `EmergencyStatus` unchanged. No kernel/wire/canonical-hash change. Additive MINOR on `@adjudicate/admin-sdk`.

## Test coverage

`packages/admin-sdk/tests/configuration-integrity-trpc.test.ts` — `deriveSealViolations` per report shape (digest mismatch + `seal_mismatch` linkage, signature fail, signature missing under `require_signature`, residual policy error without double-counting); schema round-trips + closed-enum guard (rejects an unknown `stability`); `configSealStatusAll` (entries + violations, PRECONDITION_FAILED, no single-pack regression); `killSwitchTimeline` (threaded report, PRECONDITION_FAILED). Console `/integrity` page component test (Active seals table / Drift status / empty / loading / error; structured violation chip + conditional audit linkage; stability badge per class with color-independent label; degrade-to-raw-log on timeline error; Control cross-link). Web `integrity-transparency` projection test (aggregate counts, allowlisted keys only, drops injected digest/reason/actor/headline/signature, no per-pack `packId` leak, determinism).

## Lifecycle

New `@adjudicate/admin-sdk` symbols (`governance.configSealStatusAll`/`governance.killSwitchTimeline`; `PackConfigSealEntrySchema`/`ConfigSealStatusAllResultSchema`/`SealViolationSchema`/`SealViolationKindSchema`/`KillSwitchTimelineReportSchema`/`KillSwitchStabilityClassSchema`/`KillSwitchEventSourceSchema` + inferred types; `deriveSealViolations`; `AdminContext.configSealReports?`/`killSwitchTimeline?`) ship in the combined WS3 MINOR wave with `.changeset/configuration-integrity.md` and V1_FREEZE_MATRIX rows (added in the Phase-E backfill — not in this PR). The existing `analyzeKillSwitchTimeline` row (§29.3) is unchanged — it remains the producer. Console/web are app-only. The `projectIntegrityTransparency` allowlist is an app-level contract in `apps/web`: any new field must be consciously added with a "is this safe to publish?" sign-off.
