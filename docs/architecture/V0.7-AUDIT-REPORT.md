# v0.7 — operational hardening + ecosystem trust audit report

> **Status.** Cut against `main` on 2026-05-20. Tests: **1022 passing, 1 skipped, 0 failing** (baseline 924). All v0.7 work is additive — no kernel breaking changes, no wire-format changes, no invariant relaxations.

---

## Scope

v0.7 is the **operational discipline + ecosystem trust** cut. The architectural surface lands in v0.6 (adapter-core extraction, OpenAI parity, Tier 2 AST analyzer). v0.7 adds:

1. **Real-time event substrate** — `AuditEventBus` + `bridgeAuditSinkToBus` so adopter consoles can fan out audit emissions sub-100 ms without changing the durable-sink contract.
2. **Distributed kill switch v2** — Redis pub/sub propagation with polling fallback (ADR-114). Sub-100 ms transitions; fail-closed and split-brain-free under all tested failure modes.
3. **Pack trust primitives** — `computePackFingerprint`, `verifyPackSignature`, `verifyPackTrust`, plus `adjudicate pack verify` CLI (ADR-115). Local, deterministic, ed25519 + RSA-PSS.
4. **Replay verification expansion** — `replayWithIntegrity` adds audit-hash + envelope-hash tamper detection alongside the existing decision-kind + basis-flat-set comparison. Cross-runtime golden vectors extracted to `docs/specs/canonical-hash-vectors.json` so non-Node runtimes can self-verify.
5. **Restart-durable confirmations** — `createRedisConfirmationStore` so REQUEST_CONFIRMATION tokens survive process restarts. Wraps the same `RedisLedgerClient` surface other audit components already use.
6. **Adapter loop trace hooks** — `TraceSink` + `AdapterTraceEvent` low-cardinality lifecycle events (iteration_start / decision_emitted / paused / completed / max_iterations_exceeded). High-cardinality data (payloads, history) stays on the existing `AgentEvent` stream.
7. **Operator-readable replay narration** — `explainReplayReport` translates `ReplayReport` / `ReplayIntegrityReport` into three output formats (ci-line / summary / operator).
8. **Resilience + chaos tests** — burst-of-malformed-messages, disconnect/reconnect, trip/clear storm convergence, multi-replica race, subscribe-leak detection, corrupted replay envelopes (100+ at a time).

## Operational maturity

### Scaling readiness

| Surface | v0.6 state | v0.7 state |
|---|---|---|
| Console live tail | 2 s polling | **Primitives in place** (`AuditEventBus`). Console hook migration deferred; polling fallback retained. |
| Kill switch propagation | 1 s polling | **Sub-100 ms** via Redis pub/sub; polling retained as fallback (ADR-114). |
| Confirmation persistence | In-memory only | **Restart-durable** via `createRedisConfirmationStore`. |
| Audit fan-out | Multi-sink + buffered + persistent-buffered | Unchanged. `AuditEventBus` orthogonal. |

### Resilience quality

Failure-mode coverage added in v0.7:

- Burst of malformed pub/sub messages (50 in a tight loop) — no propagation crash.
- Trip→clear→trip storm (20 transitions in a tight loop) — every replica converges on the last state.
- Multi-replica concurrent trip — last-write-wins on Redis, no split-brain.
- Subscribe/unsubscribe storm (30 cycles) — no listener leaks.
- Pub/sub disconnect mid-incident — polling fallback converges within `pollMs * 2`.
- 100 corrupted envelopes through replay — all surface as integrity failures, no crash.
- Concurrent replay of 1000 records — deterministic; 5 parallel passes produce byte-identical reports.

### Replay trustworthiness

- `replay()` (v0.6) checks decision kind + basis flat-set only.
- `replayWithIntegrity()` (v0.7) adds:
  - Envelope-level `intentHash` verification (re-derives from `(version, kind, payload, nonce, actor, taint)`).
  - AuditRecord-level `auditHash` verification (re-derives from canonical(record \ { auditHash, signature })).
  - Per-axis failure surfaces — operators see "decision matched but record tampered" as its own quadrant.
  - pre-v4 records (missing `auditHash`) tracked in `preV4Records` so migration progress is visible without false-positives.

### Event-system robustness

- `AuditEventBus` contract is explicitly best-effort. Durable writes commit first; bus failure surfaces via `onBusFailure` callback but does NOT roll back the audit record.
- `createInMemoryAuditEventBus` snapshot-iterates subscribers so handler unsubscribe mid-fan-out preserves the current dispatch.
- `createRedisAuditEventBus` is lazy: SUBSCRIBE issued only on first handler, UNSUBSCRIBE on last. No always-on Redis connection cost.

| `runConformance` | `@adjudicate/conformance` | yes |

All trust primitives are pure functions — no I/O, no global state, no hidden dependencies. The CLI command `adjudicate pack verify` is the side-effectful wrapper that reads from disk; the primitives stay testable in isolation.

### Provenance guarantees

- Fingerprint covers the DECLARATIVE Pack subset (`id, version, contract, intents, signals, basisCodes`). Re-bundling the same source produces the same fingerprint — publishers sign once, adopters verify across builds.
- ed25519 (RFC 8032) is the recommended signature algorithm. RSA-PSS is supported for environments without ed25519 support.
- Cross-algorithm misuse (signing with ed25519 + verifying with an RSA key) is detected as `key_algorithm_mismatch` — a separate failure mode from `signature_mismatch` for operator clarity.

### Trust verification coverage

- 19 conformance tests (`pack-trust.test.ts`) — fingerprint determinism, signature round-trip, tamper detection, policy enforcement, compound failure.
- 6 CLI tests (`pack-verify.test.ts`) — end-to-end against the real PIX Pack with generated keys.

## Performance posture

No measurable regressions in v0.7. All additions are opt-in primitives outside the kernel hot path:

- `replayWithIntegrity` is a verification-time helper — not in the `adjudicate()` path.
- `AuditEventBus.publish` runs after the durable sink commits — does not gate adjudication.
- `TraceSink.onTrace` is called by the adapter loop (not the kernel) and defaults to a no-op (zero allocation).
- Kill-switch v2 reads the same in-process snapshot; pub/sub only accelerates how quickly the snapshot updates.
- Pack fingerprinting is sha256 over a small canonical-JSON string — ~µs scale, never in the hot path.

Microbenchmark baseline from v0.5 still holds: kernel p99 0.7 µs EXECUTE, 6.5 µs REWRITE; full-path REFUSE p99 9.5 µs. `pnpm -F adjudicate-bench bench` to re-confirm.

## Remaining risks (pre-v1.0)

| Area | Risk | Mitigation status |
|---|---|---|
| **WebSocket bridge in console** | The `AuditEventBus` primitive lands; the console hook migration to it is deferred. Adopters running the reference console still see 2 s polling. | Primitive shipped; console migration is a console-side task — does not block any back-end work. |
| **Restart durability for parked DEFER** | `createRedisConfirmationStore` handles REQUEST_CONFIRMATION. `parkDeferredIntent` already uses Redis. The combined surface needs an end-to-end "restart mid-flow, every pending pause survives" integration test. | Surface complete; integration test deferred to v0.8. |
| **`verifyParkedHash` default mode** | Currently `"warn"`. Production should tighten to `"strict"` before v1.0. Today's default is permissive: tampered blobs fail-closed, but legacy blobs without verification fields still resume. | Default flip is a one-line change + migration note; gated on adopter feedback. |
| **L2 stability tier** | The 4 newer primitives (`createRewriteGuard`, `createConfirmGuard`, `createEscalateGuard`, `createIdempotencyGuard`) ship as `0.x` minor-unstable per ADR-108. v1.0 should either freeze them as-is or redesign based on Pack #4–#6 feedback. | No new Packs added in v0.7; same status as v0.6. |
| **Tier 2 analyzer expansion** | `AJD-201` (REWRITE scope) ships. `AJD-202` (basis vocabulary AST), `AJD-203` (guard-ordering AST) are still future work. | Tracked in `PROJECT_STATUS_AND_NEXT_STEPS.md`. |
| **Pack registry indexer** | Manifest validation primitive exists. A hosted indexer that crawls npm and lists conformant Packs is still design-only. | Deferred — adopters install Packs from npm directly without an intermediary. |
| **Sigstore / OIDC / Rekor** | v0.7 trust primitives are local + algorithm-agnostic. Sigstore is a layer on top; an adopter mapping it to `PackSignature` proves feasibility but isn't shipped. | Local trust covers the immediate use cases. Hosted signing remains a future option. |

## Operational evidence required before v1.0

Concrete adopter feedback (not framework speculation) on:

1. **Kill-switch v2 propagation latency** in a real multi-replica deployment under load.
2. **`AuditEventBus` throughput** when wired into a real WebSocket bridge with hundreds of concurrent operator sessions.
3. **Pack trust workflow** when a publisher rotates their signing key — does `verifyPackTrust` give a clear error path?
4. **Restart recovery** for a long-paused REQUEST_CONFIRMATION token across a rolling deploy.
5. **Replay-with-integrity report readability** when an actual integrity failure fires in production. (Synthetic tampering passes; real-incident triage UX is unproven.)
