# ADR-135 — Token Governance (tenant + session budgets, exhaustion timeline)

- **Status:** Accepted
- **Date:** 2026-06-07
- **Scope:** `@adjudicate/adapter-core` (`TokenUsageStore` + `createInMemoryTokenUsageStore` + the `TokenUsageSample`/`TokenBudgetConfig`/`SessionConsumption`/`TenantConsumption`/`TokenExhaustionEvent` types), `@adjudicate/admin-sdk` (`governance.tokenBudgetByTenant` + `TokenScope`/`TokenBudgetTenant`/`TokenExhaustionEvent`/`TokenBudgetTenantQuery`/`TokenBudgetByTenantResult` schemas + additive optional `TokenBudgetResult.tenants`/`exhaustionEvents` + `ActorSchema.tenantId` + `extractActor` tenant header + `AdminContext.tokenBudget.queryByTenant`), apps/console (Token Governance `/tokens` section), apps/web (public `/transparency/tokens` burn-down).
- **Related:** ADR-120 (token-budget guard + `onTokenUsage` provider-usage seam — the upstream signal this folds, and the enforcement primitive this surface must NOT become a substitute for), ADR-128 (web-parity platform / dual-app contract — the public-redaction posture this view inherits).

## Context

`governance.tokenBudget`, its wire schemas, and the `AdminContext.tokenBudget` port already exist (ADR-120), but the surface is **session-only, fixed, and faked**: there was no shipped store (port only), no tenant shape at all, and budget exhaustion was not observable as a reviewable event. The reference console hand-rolled a 3-row `DEMO_TOKEN_SESSIONS` literal at a single fixed 50k cap.

The real upstream signal already flows: `adapter-core` fires `onTokenUsage({ sessionId, iteration, usage })` once per iteration after `bridge.send` (defensively — a throwing observer is logged and ignored), `TokenUsage = { inputTokens?, outputTokens? }` is explicitly NOT hashed, and the Anthropic/OpenAI bridges map provider usage through. What was missing is a **store** to fold that hook into per-session AND per-tenant counters + exhaustion events, a **tenant dimension** to scope it, and the **SDK surface** to read it.

## Decision

- **`@adjudicate/adapter-core` (MINOR):** ship a `TokenUsageStore` interface + `createInMemoryTokenUsageStore`, mirroring the existing `createInMemoryMemoryStore` / `createInMemoryConfirmationStore` (Map-backed ref impl, opportunistic LRU bound, fixed-capacity event ring). It is fed by the adopter's `onTokenUsage` callback via `record(sample)`, accumulates per-session AND per-tenant cumulative consumption against configured caps, and appends a bounded `TokenExhaustionEvent` when a counter **crosses** its cap (once per crossing, not per over-budget sample). It exposes `sessions()` / `tenants()` / `exhaustionEvents()` / `totalConsumed()` read methods the admin port adapts. Redis is noted as a follow-up (the in-memory store + the `TokenUsageStore` interface ship now; the existing redis store pattern can mirror onto the interface without a surface change).
- **`@adjudicate/admin-sdk` (MINOR):** add `TokenScopeSchema` (closed `session`|`tenant`), `TokenBudgetTenantSchema`, `TokenExhaustionEventSchema`, `TokenBudgetTenantQuerySchema`, `TokenBudgetByTenantResultSchema`; extend `TokenBudgetResultSchema` with **additive optional** `tenants?`/`exhaustionEvents?` (the session-only shape stays byte-compatible); add `governance.tokenBudgetByTenant` (PRECONDITION_FAILED when `ctx.tokenBudget.queryByTenant` is absent — the same runtime feature-detection posture as every other `governance.*` read); widen `AdminContext.tokenBudget` additively with an optional `queryByTenant`.
- **Minimal tenant model (admin-sdk, MINOR):** add an **additive-optional** `tenantId` to `ActorSchema` and have `extractActor` read `x-adjudicate-actor-tenant`. This realizes the pre-existing `AuditQuerySchema.tenantScope` convention (documented as resolved "from `ctx.actor` (e.g. `actor.tenantId`)") with a real field. Single-tenant adopters omit it.
- **Console (app-only):** the `DEMO_TOKEN_SESSIONS` literal is replaced by a real `createInMemoryTokenUsageStore` seeded via `record(...)` with deterministic demo samples (fixed timestamps) across two tenants and four sessions — deliberately crossing one session cap AND one tenant cap so the timeline is populated. A dedicated `/tokens` section renders Tenant budgets (burn bars), Session budgets (existing per-session view + tenant chip), and an Exhaustion-events timeline.
- **Web (app-only):** a public `/transparency/tokens` view fed by a committed *illustrative* single-tenant fixture, projected to an **aggregate-only, id-free, coarsely-rounded, banded** burn-down (`pctUsed`, `band`, `≈` display strings) — never session ids, tenant ids, per-session rows, exhaustion details, or raw counts.

## Determinism — the load-bearing invariant

**The store is TELEMETRY, strictly OUTSIDE the determinism boundary, and is NEVER a guard/kernel input.** Enforcement stays in `createTokenBudgetGuard` (ADR-120), whose only inputs are `(envelope, adopter state S)` — it reads the consumed counter from `S` via `extractSessionTokens`/`extractTenantTokens`, *not* from this store. The store and the guard are two INDEPENDENT reads of the same upstream provider usage: the guard reads it folded into `S` (deterministic, kernel-facing); the store reads it from `onTokenUsage` (telemetry, dashboard-facing). There is no edge between them.

Honored by construction:

- **No wall-clock on any recorded value.** Every `at` is adopter-supplied (`record(sample)` uses `sample.at` verbatim for `lastAt` and any event `at`). The only `Date.now()` in the module is the same opportunistic LRU sweep `createInMemoryMemoryStore` already uses — it evicts old rows, never participating in a recorded value or a decision.
- **No RNG on any path.** Exhaustion-event ids are a monotonic insertion sequence (`evt:<n>`), not `crypto.randomUUID()`, so the store stays reproducible across runs/replays. Ids are telemetry only — never hashed, never a kernel input.
- **Replay safety.** Replaying an envelope re-derives the same Decision from `(envelope, policy, S)`; the store is not consulted, so it cannot perturb replay. ADR-120's deep-frozen-`S`-adjudicated-twice property is unaffected — this design adds no new guard input. Best-effort hook loss only undercounts telemetry, never a Decision. Counters are commutative sums, so cumulative totals are order-insensitive.
- **No hash touched.** `TokenUsage` is "NOT part of any hash"; the store never touches the envelope, the canonical-hash recipe, or `S`. `TokenExhaustionEvent` is a denormalized read-model — NOT an `AuditRecord` field and NOT a `GovernanceEvent` taxonomy entry (those are unchanged). The actual REFUSE/DEFER is already a normal audited, replayable kernel Decision in the ledger (`business.RULE_VIOLATED`); the event is a timeline read-model only.

## Bounded cardinality + the session-churn-evasion mitigation

Session counters are LRU-bounded (`maxSessions`, default 10_000); exhaustion events live in a fixed-capacity newest-first ring (`maxEvents`, default 10_000, mirroring `DEFAULT_MAX_EMERGENCY_EVENTS`); tenant counters are bounded by real tenant cardinality.

**Budget evasion via session-id churn → the tenant cap is the backstop.** An adversary minting a fresh `sessionId` per request resets the SESSION counter and slips under any per-session cap. The TENANT cap aggregates across ALL of a tenant's sessions regardless of churn, so churn within a tenant still trips `tenantBudget` and records a `scope: "tenant"` exhaustion event. The LRU bound means a flood of throwaway session ids evicts old session rows rather than exploding memory (and shows up as an anomalous `sessionCount` on the tenant row). A tenant counter survives even when its sessions are LRU-evicted. This is why threading the tenant dimension is the load-bearing part of the design, not a nicety.

## Security / redaction

Token counts, session ids, and tenant ids are business-sensitive (they leak customer scale, usage, and identity). The **console** (authenticated operator, fail-closed bearer + `x-adjudicate-actor-*`) may see full per-session/per-tenant rows and raw event details. The **public web** view must NOT, and cannot by construction: its projection reads only a single aggregate `consumed`/`budget` pair and emits a shape with NO field for any id, per-session row, or exhaustion detail — counts are additionally coarsened (rounded + `≈`) and the precise pct is bucketed into a 3-value band, so an attacker cannot confirm "my injected loop drove cost up". `extractActor` does NOT authenticate; a publicly-mounted route lets a caller forge `x-adjudicate-actor-tenant` — tenant isolation is enforced by the adopter's middleware + the store's tenant filter, exactly as the existing `tenantScope` contract requires.

## Invariants preserved

No kernel change. No closed-enum widening of any KERNEL enum (Decision-6 / Taint / IntentActor / BasisCategory untouched); the only new enum, `TokenScopeSchema`, is admin-sdk-local and closed (`session`|`tenant`). Wire format is append-only: `TokenBudgetResult` gains only OPTIONAL fields, `governance.tokenBudget` stays byte-compatible, `ActorSchema.tenantId` is optional. Canonical-hash recipe unchanged. Apps are app-only.
