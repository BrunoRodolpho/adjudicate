# ADR-132 — Behavioral Drift history surface

- **Status:** Accepted
- **Date:** 2026-06-07
- **Scope:** `@adjudicate/drift` (`createDriftHistory` + `DriftHistory`/`DriftHistoryEntry`/`DriftHistoryDimensionEntry`/`DriftHistoryView`/`DriftHistoryOptions`), `@adjudicate/admin-sdk` (`governance.driftHistory`; `DriftHistoryEntry`/`DriftHistoryDimensionEntry`/`DriftHistoryResult` schemas + `DriftHistoryQuery`; `AdminContext.driftHistory?`), apps/console (unified `/drift` page reconciling the two split panels), apps/web (public behavioral-drift status badge).
- **Related:** ADR-119 (`@adjudicate/drift` — `createDriftDetector`/`DriftSnapshot`/`governance.behavioralDrift`, bounded-cardinality + count-windowed determinism), ADR-128 (cross-cutting web-parity platform / dual-app transparency contract + chart kit). Also ADR-114 (AuditEventBus live feed). Design doc: `docs/roadmap/design/behavioral-drift.md`.

## Context

Behavioral drift was split across two unreconciled console panels and frozen in time. The **statistical** signal (`BehavioralDriftPanel`, ADR-119) renders the single-point `governance.behavioralDrift` snapshot — per-dimension TVD + alerts, computed once at startup by replaying `ALL_MOCKS` into the detector. The **operational** signal (`DriftPanel`) client-aggregates six integrity-violation refusal codes from `audit.query`. Two deeper gaps: there was **no time-series** (`snapshot()` is one point — an operator can't tell whether a TVD spike is new, recovering, or sustained), and the unified "Drift" section the roadmap wants (active drifts, dimensions, a timeline, severity) did not exist. WS3 web-parity also requires a sanitized public drift status.

## Decision

- **`@adjudicate/drift` — `createDriftHistory({ capacity? })`** (additive MINOR): a bounded, deterministic snapshot-history accumulator. `record(snapshot, at)` appends a per-dimension TVD + alert-count roll-up of a `DriftSnapshot`, stamped with a CALLER-SUPPLIED `at` + a monotonic, eviction-stable `seq`. `view()` returns `{ capacity, count, dropped, entries }` (oldest → newest). A fixed-capacity ring buffer (default 100), oldest evicted first; `dropped` exposes eviction so a dashboard never silently loses history. NO wall-clock and NO RNG on any path — the package never reads a clock; timestamps are supplied by the adopter. New types `DriftHistory`/`DriftHistoryEntry`/`DriftHistoryDimensionEntry`/`DriftHistoryView`/`DriftHistoryOptions`.
- **`@adjudicate/admin-sdk` — `governance.driftHistory`** (additive MINOR): a `.query(DriftHistoryQuerySchema)` (`{ limit }`, default 100, max 500) → `DriftHistoryResultSchema` (`{ schemaVersion: 1, capacity, count, dropped, entries: DriftHistoryEntry[] }`, each entry `{ at, seq, totalObserved, maxTvd, alertCount, dimensions: { dimension, tvd, alertCount }[] }`). Schemas re-declare the `DriftHistoryView` shape as Zod with NO dependency on `@adjudicate/drift` — the same dependency-free posture `BehavioralDriftResultSchema` (ADR-119) takes. New `AdminContext.driftHistory?: { query(input): DriftHistoryResultParsed }`; PRECONDITION_FAILED when absent — identical runtime feature-detection to `driftDetector`/`behavioralDrift`. `behavioralDrift` is unchanged.
- **Console:** a unified `/drift` page (new Sidebar item "Drift", `TrendingUp`) with four clearly-labelled sub-views — **Active Drifts** (statistical TVD alerts, severity band = magnitude / threshold, sorted high → low, from `behavioralDrift`), **Dimensions** (per-dimension TVD + alert count), **Timeline** (`<TimelineChart>` of max-TVD per recorded snapshot from `driftHistory`, with a `dropped > 0` truncation caption), and an explicitly-labelled **Operational** sub-view embedding the existing integrity-code `DriftPanel`. Statistical (TVD) vs Operational (integrity) is labelled at every boundary so the two are never conflated. The existing `BehavioralDriftPanel` and dashboard `DriftPanel` stay where they are; `/drift` is the unified home.
- **Console route wiring:** the reference console builds a real, DETERMINISTIC demo timeline — it replays `ALL_MOCKS` into the detector in CHUNKS (quarters) and, after each chunk, records `driftHistory.record(detector.snapshot(), at)` with evenly-spaced ISO timestamps derived from a FIXED base (`2026-01-01`, ~one-quarter step) — no wall-clock, so the history is byte-stable across restarts. When a live `AuditEventBus` is attached the detector observes live, and an adopter records snapshots on their own cadence with a harness-supplied clock. The existing `driftDetector` snapshot wiring is intact.
- **Web:** a public, read-only `/transparency/drift` status fed by a committed *illustrative* fixture projected through the **aggregate-only, banded** `projectDriftTransparency` — a coarse severity band (ok / elevated / high), the active-alert count, and the single top-drifting dimension NAME, plus `asOf`. No category maps, raw TVD numbers, baseline/recent counts, `__overflow__` buckets, or timeline entries ever cross the boundary.

## Why this shape

- **Additive, pattern-matched.** `createDriftHistory` is additive on `@adjudicate/drift`; `governance.driftHistory` mirrors the established context-read + PRECONDITION_FAILED idiom (sibling to `behavioralDrift`); the SDK schema carries no `@adjudicate/drift` dependency, exactly like `BehavioralDriftResultSchema`. No new store, no kernel change, no producer change.
- **Determinism by construction.** `record(snapshot, at)` is a pure append; the ring buffer's FIFO eviction is total; `seq` is a pure monotonic counter that survives eviction (so a dropped entry never collapses two points onto one `seq`) and is intentionally NOT reset by `reset()`. The package calls neither `Date.now()` nor RNG — timestamps are caller-supplied, mirroring `DriftSnapshot`'s clock-free design and the kernel rule that the harness owns time. The console replay derives its stamps from a fixed base.
- **Public-leak defense in depth.** A `new_category` signal echoing an injected category VALUE on a public surface would confirm to an attacker that their injected intent kind landed. The public projection is an allowlist whose output type cannot even carry a category value, a raw TVD, or a timeline entry — only a banded class + a count + a public-vocabulary dimension name.

## Invariants preserved

- **Outside the determinism/taint boundary.** The kernel never imports `@adjudicate/drift` (ADR-119 ships a dependency-direction test). Nothing here reaches `intentHash`/`adjudicate()`/policy/state. The ring buffer is in-process telemetry, never a system of record — loss or tampering degrades observability only; the durable, hash-chained audit ledger remains the governance source of truth. Drift reads `decision.kind`/`envelope.kind`/`decision_basis[].category` only and never mutates records, so it cannot perturb the taint lattice. The operational sub-view surfaces `rewrite_taint_regression` as a count for display; it does not re-derive taint.
- **Bounded cardinality (ADR-119 discipline).** Retention is capped at `capacity`; each retained snapshot is already category-bounded by the detector (`maxCategoriesPerDimension` + `__overflow__`). Total retained payload is fixed; `dropped` makes eviction visible.
- **No closed-enum widening.** `DriftDimension` (3) and `DriftSignalKind` (3) are unchanged; the SDK re-declares the dimension name as `DriftDimensionNameSchema` byte-equal to the producer. No new `GovernanceEvent` taxonomy — snapshots are telemetry, never an audit field. No kernel/wire/canonical-hash change. Additive MINOR on `@adjudicate/drift` and `@adjudicate/admin-sdk`.

## Test coverage

`packages/drift/tests/history.test.ts` — recording (monotonic `seq` + supplied `at`, defensive view copy, default capacity 100); capacity/eviction (FIFO + `dropped`, floor non-positive/non-finite/fractional capacity, `reset` clears entries+dropped but keeps `seq` monotonic); derived `maxTvd`/`alertCount` (max + sum, empty-dimension snapshot); determinism (byte-identical over the same `(snapshot, at)` sequence, real detector replay). `packages/admin-sdk/tests/drift-history-trpc.test.ts` — schema round-trips + closed-enum/ISO guards + `limit` bounds; `governance.driftHistory` (windowed timeline honouring `limit`, default limit, `dropped` surfaced, PRECONDITION_FAILED, no `behavioralDrift` regression). Console `/drift` page component test (`severityBand` banding; Active Drifts sorted high→low with severity bands / healthy-empty / loading / not-configured error; Dimensions rows + insufficient-observations empty; Timeline chart / truncation caption / empty / error; labelled Operational sub-view). Web `drift-transparency` projection test (banded aggregate, ok/elevated/high, deterministic, allowlisted keys only, drops injected category map / baseline / recent / overflow / timeline, never emits a raw TVD, publishes only a dimension name).

## Lifecycle

New `@adjudicate/drift` symbols (`createDriftHistory` + `DriftHistory`/`DriftHistoryEntry`/`DriftHistoryDimensionEntry`/`DriftHistoryView`/`DriftHistoryOptions`) and `@adjudicate/admin-sdk` symbols (`governance.driftHistory`; `DriftHistoryEntrySchema`/`DriftHistoryDimensionEntrySchema`/`DriftHistoryResultSchema`/`DriftHistoryQuerySchema` + inferred types; `DriftDimensionNameSchema` re-export; `AdminContext.driftHistory?`) ship in the combined WS3 MINOR wave with `.changeset/behavioral-drift-history.md` and V1_FREEZE_MATRIX rows (added in the Phase-E backfill — not in this PR). The existing ADR-119 drift rows are unchanged. Console/web are app-only. The `projectDriftTransparency` allowlist is an app-level contract in `apps/web`: any new field must be consciously added with a "is this safe to publish?" sign-off.
