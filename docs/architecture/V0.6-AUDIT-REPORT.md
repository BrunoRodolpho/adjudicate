# v0.6 — Second-Phase Architectural Audit Report

> Scope: provider abstraction, analyzer hardening, conformance alignment, Pack-ecosystem foundations, DX improvements. Kernel API frozen; load-bearing invariants verified.

## Architectural improvements

### Extracted systems

- **`@adjudicate/adapter-core`** — provider-neutral orchestration layer carved out of the Anthropic adapter. Owns the tool-use loop, the bridge primitives, the Decision translator, persistence shims, and the error taxonomy. ADR-113 documents the contract and migration.
- **`@adjudicate/openai`** — reference OpenAI Chat Completions integration. Thin SDK shim over adapter-core; no hard `openai` SDK dependency (uses a structural `OpenAIChatLikeClient` interface). Closes the largest single adoption blocker — OpenAI is ~70% of adopter LLM volume.
- **Tier 2 AST analyzer (`AJD-201`)** — `ts-morph`-based REWRITE scope check in `@adjudicate/analyze`. Walks the actual source AST to verify a guard's declared `mutatesPayloadFields` matches what the rewritten envelope literal touches. Emits source-located diagnostics with fix hints; SARIF-compatible.
- **Pack manifest validation primitive (`validatePackManifest` / `crossCheckPackVsManifest`)** — lives in `@adjudicate/conformance`. Validates the npm-convention `adjudicate` field in `package.json` and cross-checks against the live Pack. Consumed by CLI, future registry indexer, install hooks.

### Reduced coupling

- The Anthropic adapter loses 80% of its line count. It now does three things: build a `ProviderBridge<MessageParam[]>`, hand it to adapter-core, return the typed agent surface. Every load-bearing concern (audit wiring, replay safety, defer/confirm orchestration, REWRITE handling, confirmation-blob hash verification) lives upstream.
- The OpenAI adapter does the same thing in a different SDK shape. Cross-provider parity is **structural** — invariant preservation is inherited from adapter-core, not re-asserted per provider.
- Provider-specific knowledge is confined to three files per adapter: `bridge-<provider>.ts`, `renderer-<provider>.ts`, `<provider>-types.ts`.

### Provider-portability gains

- **Adding a third provider is a < 200-line PR.** Implement `ProviderBridge<YourHistoryShape>`, add a provider-tuned renderer, re-export `createAdjudicatedAgent` wired to adapter-core. Done. Demonstrated end-to-end by the OpenAI integration tests against the same PIX-Pack conversation that exercises every Decision kind.
- **No hard SDK dependencies in adapter packages.** `@adjudicate/openai` uses a structural type for the client (`OpenAIChatLikeClient`); the official `openai` SDK satisfies it, mocks satisfy it, Azure OpenAI wrappers satisfy it. Same pattern available for the next provider.

### Invariant-strengthening wins

- **`KERNEL_REFUSAL_CODES` includes `guard_panic`.** The `KERNEL_INTERNAL_REFUSAL_CODES` overlay in `@adjudicate/conformance` is removed; one less place for refusal-code drift to hide. Single source of truth in `packages/core/src/pack-conformance.ts`.
- **`assertPackConformance` vs `runConformance` split documented prominently.** The boot-time / runtime / CI three-surface model is now in the module header where every reader sees it. Adopters wiring a new Pack pick the right surface at the right call site without re-discovering the distinction.
- **Tier 2 AJD-201 closes the structural promise of mutatesPayloadFields.** Tier 1 verified the *declaration*; Tier 2 verifies the *actual mutations*. Undeclared mutations now fail CI.
- **`explainRecord` supersession narration.** AuditRecord v3+ supersession links render as one-line narrations. Default templates cover `confirmation_resolved`, `defer_resumed`, `rewrite_executed`, `replay`. Operators viewing a single record follow the chain back without joining tables.

### Provider readiness

- **Anthropic**: thin shim; public API preserved across v0.5 → v0.6 via re-exports. Existing adopters don't change source.
- **OpenAI**: reference implementation; structural client typing; PIX-Pack parity tests.
- **Vercel AI SDK, Gemini, Bedrock**: not yet shipped, but each is a < 200-line PR against the now-stable `ProviderBridge<H>` contract.

### Pack readiness

- **Manifest validation**: shipped. Adopters can validate a candidate Pack's `package.json` before installing.
- **Live-Pack ↔ manifest cross-check**: shipped (`crossCheckPackVsManifest`). Catches drift between declared `intents` / `signals` and what the live Pack actually exports.
- **Registry indexing**: design intact; the validation primitive is the missing piece the indexer needed.
- **Signing**: still design-only.

### Operational maturity

- Replay determinism: unchanged. Cross-provider parity tests assert identical event-log fingerprints for two runs against the same canned conversation, on both providers.
- Audit integrity: unchanged. Every intent envelope crosses `adjudicateAndAudit` regardless of provider.
- Fail-closed semantics: unchanged. Guard exception isolation (ADR-106), kernel-deadline path, kill-switch path all preserved.

### Observability maturity

- No new SEMCONV constants. The provider-neutral event stream (`AgentEvent`) uses the existing vocabulary — the type change for `tool_result.payload` is structural (provider-neutral block instead of Anthropic-specific), not semantic.

## Remaining risks

### Unresolved tradeoffs

- **`AgentEvent.tool_result.payload` shape change is a breaking surface change for Anthropic adopters.** Existing adopter UI code that pattern-matches `payload.is_error` must migrate to `payload.isError`. Documented in `.changeset/v0.6-adapter-core-openai.md`. The trade-off (slight breaking change vs perpetual two-shape duplication) was made deliberately; reverting would either erase OpenAI's parity or fork the AgentEvent type.
- **`AnthropicAdapterError` / `AnthropicAdapterErrorCode` deprecated aliases.** Currently aliased to `AdapterError` / `AdapterErrorCode`. v2.0 removes them. No codemod ships yet for this rename — adopter migration is one find/replace per file.

### Deferred work (intentional)

- **WebSocket bridge for the operator console** — kept on the priority list. The status doc moved it to Priority 1 (operational scalability). The architecture target is NATS + WebSocket; today's 2s polling stays as fallback. Adopters with high-fan-out consoles will hit this first.
- **Pub/Sub kill switch v2** — same priority bucket. 1s Redis poll today; Pub/Sub would drop propagation to < 100ms. Polling stays as the safety net.
- **Vercel AI SDK adapter** — easy to ship now that `ProviderBridge<H>` is stable; pending adopter demand.
- **`PolicyConfig` externalised tunables** — explicitly deferred until the first adopter hits the gap. No speculation.
- **Outcome reconciliation API (`recordOutcome`)** — `LearningSink` substrate is in place; the canonical sink is one ticket but lands no value without a consumer.

### Future v1.0 concerns

- **`verifyParkedHash` default** is still `"warn"`. Pre-v1.0 should tighten to `"strict"`. Today's default is permissive: tampered blobs fail-closed, but legacy blobs without verification fields still resume.
- **L2 stability tier**. The four newer primitives (`createRewriteGuard`, `createConfirmGuard`, `createEscalateGuard`, `createIdempotencyGuard`) ship as 0.x minor-unstable per ADR-108. v1.0 either freezes them as-is OR redesigns based on Pack #4–#6 feedback.
- **Wire-format change risk before JSON Schema saturation**. Any envelope-shape change must land *after* its JSON Schema and golden vectors, or external-runtime replay breaks. Current discipline (intent-envelope-v2.schema.json + canonical-json-hash.md + Python cross-runtime check) protects this; no change planned.
- **Closed enum doctrine on `Decision`**. Six outcomes is the load-bearing closed vocabulary. The v0.6 cycle did not widen it; future cycles must resist `Decision.metadata?: Record<string, unknown>` escape hatches and `Decision.confidence` field-level proposals.

## Invariant verification

The following are **explicitly confirmed** preserved through the v0.6 cycle:

### Replay safety preserved

- `adjudicate()` remains synchronous, pure, deterministic. No `Date.now()`, no `Math.random()`, no I/O.
- The cross-provider parity test in `packages/openai/tests/integration-pix.test.ts` asserts byte-identical event-log fingerprints for two runs of the same canned conversation. Same on the Anthropic side.
- 346 → 356 core kernel tests passing (the +10 is the `explainRecord` extensions; no kernel-flow tests changed).

### Hashing stability preserved

- `intentHash` is RFC 8785 JCS over `{version, kind, payload, nonce, actor, taint}`. Unchanged.
- `createdAt` is excluded; `nonce` is the idempotency key. Unchanged.
- The OpenAI bridge `JSON.parse`s `function.arguments` (a JSON-encoded string from OpenAI's wire format) into a structured payload before any envelope construction, so the hash inputs are byte-identical to the Anthropic path for the same logical intent.

### Audit integrity preserved

- `adjudicateAndAudit` is the only path through which Decisions reach the executor. Provider adapters in v0.6 do not bypass it; the loop is the single point of audit emission.
- `AuditRecord` v4 schema unchanged. `auditHash`, `signature` seam, `policyVersion`, `kernelVersion` all preserved.
- The forensic-continuity invariant from P0-2 (`packages/anthropic/tests/replay-suppression.test.ts`) still passes — two sends with the same `nonce` produce one EXECUTE + one REPLAY_SUPPRESSED REFUSE; both emit audit records.

### Deterministic behaviour preserved

- `runConformance(pack)` produces byte-identical reports across runs at the same `(pack, options)`. Unchanged. The harness's seeded LCG was not touched.
- The deterministic-execution test in `packages/openai/tests/integration-pix.test.ts` asserts that the OpenAI adapter's event log is byte-identical across two runs with the same canned input.
- The Tier 2 analyzer is deterministic: same source → same diagnostics. Verified by `tests/tier2.test.ts > determinism`.

### Closed enum doctrine preserved

- `Decision` remains a 6-valued union: `EXECUTE | REFUSE | DEFER | ESCALATE | REQUEST_CONFIRMATION | REWRITE`. No widening.
- No `Decision.metadata`, no `Decision.confidence`, no escape hatches.
- The provider-neutral `ToolResultBlock` introduced in adapter-core is *not* a Decision-shape change; it's an SDK-boundary contract.
- The new `AdapterErrorCode` constants are an additive vocabulary (same closed-vocabulary discipline as `BASIS_CODES`).
